# Product vision

Usina Docs is an open platform for structuring, reviewing, translating, publishing and teaching knowledge.

## Origin

The name **Usina** represents the generation and transformation of knowledge. The `.BR` identity records the project's Brazilian origin. The AdvPL Guide is the first real-world use case and the laboratory used to validate product requirements.

## Central difference

Documentation and training use the same knowledge model. A concept, example, image or reference can be maintained once and reused in reference pages, lessons, reviews and assessments.

## Principles

1. Content belongs to the data model; presentation belongs to a renderer or theme.
2. Every save creates a recoverable revision.
3. Translations are tracked by block, not only by page.
4. Documentation and training share concepts and content blocks.
5. The core must not contain AdvPL, Protheus or TOTVS-specific assumptions.
6. Installation-specific content belongs to packages or site data.
7. Every installation can export its content in an open, versioned format.
8. Security, privacy, accessibility and source attribution are product requirements.
9. A release is installable from scratch using only its package and documentation.
10. Public reading remains lightweight and resilient.

## Product areas

### Usina Core

Sites, configuration, users, permissions, pages, revisions, blocks, languages, translations, media, taxonomies, relationships, search, themes, extensions, import, export, backup and updates.

### Usina Docs

Structured content models, catalogs, references, citations, relationships, editorial workflow and technical review.

### Usina Learn

Courses, learning paths, modules, lessons, objectives, prerequisites, exercises, assessments, error-guided review, progress, achievements and certificates.

### AdvPL package

AdvPL-specific models, syntax highlighting, content and integrations used by the AdvPL Guide. This package validates the generic platform without defining its core.

## Positioning
