# Contributing to Usina Docs

Contributions to Usina Docs are welcome, including bug fixes, improvements, new features, documentation, translations and tests.

## Pull Requests

For significant changes, consider opening an Issue first so the proposal can be discussed before implementation.

When preparing a Pull Request:

1. keep the change focused on a clear objective;
2. describe the problem or improvement;
3. summarize the main changes;
4. include or update tests when applicable;
5. update documentation when necessary;
6. preserve existing copyright and licensing notices.

## Third-party material

Do not submit code, documentation, images or other materials unless you have the right to do so.

Dependencies and material originating from other projects must have licenses compatible with their intended use in Usina Docs, and their applicable copyright and licensing notices must be preserved.

## Review process

Pull Requests are reviewed by the project maintainers. Submission of a Pull Request does not create an obligation to merge it.

Maintainers may request changes or decline contributions that do not align with the project's technical, architectural, security or licensing requirements.

## Conduct

Communication in Issues, Pull Requests and other official project spaces should remain technical, respectful and collaborative.
